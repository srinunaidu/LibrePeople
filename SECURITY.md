## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| `main` (pre-release, extraction in progress) | :warning: Best-effort triage only; NOT production-ready |
| Tagged releases | No releases published yet; support window TBD |

Once releases exist, the supported-versions table will list each
maintained line and its end-of-support date. Until then, treat `main`
as unsupported for production use.

## Reporting a Vulnerability

- **Do not** open a public issue for a suspected vulnerability.
- Report privately to: **security@example.invalid (TBD — placeholder, not
  a real inbox)**.
- Backup/alternate contact: **TBD**.
- Include: affected version/commit, steps to reproduce, impact
  assessment, and any logs (redact secrets and PII).
- You will receive an acknowledgement once a real contact is designated;
  until then reports are queued against this TBD placeholder and no
  response-time SLA is claimed.

## Disclosure Rule

- The reporter and maintainers agree on a coordinated disclosure date
  before any public description is published.
- No fixed embargo period is claimed in this prepared-only draft; the
  embargo and patch-release schedule are set case-by-case once a
  security owner is designated.
- Reporters must not disclose the issue publicly until the agreed date.
- Maintainers will publish an advisory describing the affected versions,
  the fix, and upgrade steps once a patch is available.

## Scope Notes

- Payroll, identity, and statutory data paths are always in scope for
  triage priority.
- Out of scope: social-engineering reports without a product defect,
  and findings against local-only developer tooling with no production
  path (still welcome as regular issues).
